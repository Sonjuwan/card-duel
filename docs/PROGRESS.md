# 개발 기록

## 2026-11-22 — v0.91.0 개발 후보 (실제 서버 역할 준비 검사)

- SQL 006은 기존 스키마 준비 함수에 실제 `service_role` 및 `rolbypassrls`, `row_security_active` 확인과 일반/인증 유저의 준비 RPC 권한 차단을 추가한다. 새 역할 권한 부여나 계정/경기 행 변경 없음. 스키마 5 이하는 운영 시작 차단, 모의 응답 및 SQL 정적 계약 검사 통과. 실제 PostgreSQL 미연결.

## 2026-11-22 — v0.90.0 개발 후보 (계정 장기 성장 원장 검증)

- 별도 임시 SQLite와 두 로그인 세션에 144개 합성 경기 결과(50% 승리)를 기록한다. 25랭크 각각의 실제 서버 방 AI 난이도/덱 풀과 보유 카드 추천 덱, XP 정확한 증가 및 9직업 순서, 122경기 카드 전체 해금, 144경기 최고 랭크, 18,860 XP/14개 퀘스트 완료 확인.
- 30경기마다 계정 DB 재시작, 두 세션 일치, 20경기마다 중복 재정산, 30개 표시 기록 밖의 첫 경기 재전송 무중복, 저장 덱 보존 및 더 높은 XP 문턱 패치/원복에서 획득 카드 유지 검증. 실제 대전 승률·외부 서버 검사가 아니다.

## 2026-11-22 — v0.89.0 개발 후보 (9직업 동시 부하 시험과 소환물 재사용)

- 12개 AI 경기(최고 난이도 6개)·8라운드·9직업 및 별도 보유 카드 PvP 1경기, 실제 영웅 능력 73회와 기대 계정 ID·정산 검사. 최소 2경기·1라운드 시험도 통과.
- 실제 생성된 영웅 능력 소환물을 주문으로 손에 반환한 뒤 작업 스레드 AI가 재사용할 수 있는 테스트. 개발자 분석 도구도 불변 전투 카탈로그를 사용해 소환물을 기록하고 반복 데이터 복제를 줄인다. 카드 밸런스 조정이나 학습 데이터 변경 없음.

## 2026-11-22 — v0.88.0 개발 후보 (영웅 토큰·서버 메모리)

- 신규·복원 경기 및 AI 시뮬레이션의 불변 전투 카탈로그를 통일하고 성기사·주술사 영웅 능력 하수인 5종을 포함한다. 실제 AI 작업 스레드에서 두 직업의 소환물을 가진 보드의 행동을 검사한다.
- 서버 카탈로그는 기존 경기와 신규 경기에서 공유하며 가변 경기 상태는 분리한다. 원본의 후속 카드 변경은 이전 경기의 정의에 영향을 주지 않는다. 카드 능력치와 AI 학습 원본은 변경하지 않는다.

## 2026-11-22 — v0.87.0 개발 후보 (클라우드 스키마 준비 검사)

- SQL 005의 읽기 전용 STABLE/SECURITY INVOKER 함수가 PostgreSQL 시스템 권한·RLS·원장 RPC 존재/권한만 확인한다. 게임 데이터 행을 읽지 않는다. 기존 SQL 001~004 후 적용, 기존 계정 및 경기 행 변경 없음.
- 운영 시작 및 cloud CLI는 모든 필수 열·서버 쓰기 권한·정산 RPC·공개/인증 유저 권한·RLS·스키마 버전을 확인하고 실패 시 시작 중단. 모의 정상/누락·차단 실패·잘못된 응답 시험, 실제 PostgreSQL 미검증.

## 2026-11-22 — v0.77.0 개발 후보 (클라우드 복원/인증 응답)

- 클라우드 저장 경기 조회를 기본 키 순서의 100건 페이지로 전부 읽고, 서버가 더 짧은 페이지를 반환해도 빈 페이지까지 조회한다. 중복·식별자 불일치·비정상 응답 시 시작을 거절해 부분 복원 상태로 운영하지 않는다. 모의 235건/37건 페이지 시험.

## 2026-11-22 — v0.76.0 개발 후보 (패치 갱신 및 최초 접속 복구)

- 첫 카드 요청 시간 제한·다시 불러오기, 응답 형식/해시 확인 및 HTTPS의 실제 SHA-256 검증. LAN HTTP에서 Web Crypto 미지원 시 서버 해시와 엔진 카드 검증을 유지한다. 독립 오프라인 HTML은 영향 없음.

## 2026-11-22 — v0.75.0 개발 후보 (공개 계정 보안 경계)

- 게임 페이지는 동일 출처의 정확한 WebSocket만 허용한다. HTTPS 운영 출처에는 HSTS, 모든 게임 페이지에는 동일 출처 자산 보호 및 카메라·마이크·위치·결제 권한 제한을 적용한다. 로컬 HTTP에서는 HSTS를 적용하지 않는다.
- 실제 로컬 HTTP로 정확한 운영 출처, 보안 쿠키의 속성·중복 거절, 잘못된 출처/본문, 이메일 정규화 및 위조 XFF로 로그인 제한 우회 불가를 시험한다. 배포 승인 CLI도 게임 페이지의 보안 헤더를 직접 검증한다.
