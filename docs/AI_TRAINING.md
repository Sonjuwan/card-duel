# AI 무기한 자동 학습 (Windows 10/11, v0.132부터)

게임과 독립적으로 오래 실행하며 기존 검증된 모델에서 출발합니다. Node.js 24.x만 필요하며 npm 패키지 설치, GPU, 유료 API 및 인터넷은 필요하지 않습니다(학습 프로그램 자체는 로컬 CPU에서 계산).

## 외출 전 설정

1. 학습용 ZIP 전체를 새 폴더에 압축 해제합니다. 이전 폴더와 학습 결과를 지우지 않습니다.
2. Node.js 24.x가 설치되어 있는지 확인합니다. 전원 연결 후 운영체제의 절전/최대 절전과 덮개 닫기 시 동작을 확인합니다. 화면은 꺼도 되지만 컴퓨터를 절전시키면 시뮬레이션도 멈춥니다. 통풍이 확보된 장소에 두고 먼저 10~20분간 온도·소음·안정성을 확인합니다.
3. **`START-AI-TRAINING.cmd`**를 더블클릭합니다. 1(저발열 권장), 2(균형), 3(최대 CPU) 중 선택하거나 15초 기다리면 1로 시작합니다. 콘솔을 열어 둡니다.
4. 계속 자기 대전을 실행합니다. 30분 단위로 작업자를 정상 종료·재시작하되, 기존 체크포인트에서 이어갑니다. 오류 종료 때는 30초 후 자동 재시작합니다. 완료 경기/체크포인트가 20분 동안 갱신되지 않으면 감시자가 종료를 요청하고 3분 동안 기다린 후 정지된 작업자를 강제 종료해 마지막 체크포인트부터 재개합니다. 경기 진행 없이 연속 세 번 오류가 발생하면 해당 시험/손상 체크포인트를 `recovery/`에 보존하고 정상 챔피언을 기반으로 새 시험을 시작합니다. 감시 프로그램 자체의 예기치 않은 오류도 Windows 시작 창에서 30초 후 재시도합니다. 지속적인 시스템/디스크 오류는 로그를 확인하세요.
5. 별도의 **`AI-TRAINING-STATUS.cmd`**를 실행하면 추가 경기 수, 검증된 승격 수, 자동 재시작 횟수, 최근 저장 시각을 확인할 수 있습니다. 약 1분마다 결과 파일을 갱신합니다.

## 중단·결과 업로드

- **`STOP-AI-TRAINING.cmd`**로 정상 중단을 요청합니다. 또는 기존 콘솔에서 Ctrl+C를 한 번 누릅니다. 원래 콘솔에 `Training stopped`가 표시될 때까지 기다립니다. 진행 중인 경기는 가능한 마무리하고 저장합니다.
- **`ai-training-session/AI-TRAINING-RESULT.json`** 하나를 Card Duel 프로젝트 채팅에 첨부합니다. 카드 버전 해시, 기존 대비 추가 학습량, 챔피언 가중치, 이전 챔피언, 미완료 체크포인트, SHA-256 검증값이 함께 들어 있습니다. 중단 전에도 이 파일이 자동 갱신됩니다.
- 같은 폴더에서 START를 다시 실행하면 이전 학습 상태를 그대로 이어갑니다. 강제 종료/정전 시 마지막 정상 체크포인트 이후 일부 경기만 유실될 수 있습니다. 결과 파일은 마지막 성공한 자동 저장본을 보존합니다. 컴퓨터 자체가 종료되었거나 절전 상태일 때는 학습할 수 없으며, 재부팅 후 START를 직접 실행해야 합니다.
- 정상 게임용 `data/ai` 및 `data/ai-release`와 카드 파일은 변경하지 않습니다. 결과 파일을 올리면 개발자가 카드 호환성과 모델 가중치를 검사하고, 현재 챔피언과 별도 대전에서 성능을 비교한 후 게임 반영 여부를 판단합니다. 학습 경기 수·승격 횟수만으로 실제 실력 상승이 보장되는 것은 아닙니다.

macOS/Linux의 명령줄 실행:

```sh
node apps/cli/ai-training-supervisor.ts start --power quiet
node apps/cli/ai-training-supervisor.ts status
node apps/cli/ai-training-supervisor.ts stop
```

개발자 결과 확인(읽기 전용):

```sh
node apps/cli/ai-training-result.ts ai-training-session/AI-TRAINING-RESULT.json
node apps/cli/benchmark-strength.ts 9 25 25 2 71000 2 file:ai-training-session/AI-TRAINING-RESULT.json current
```

`--session <별도 폴더>`를 지정해 다른 학습 세션을 시작할 수 있습니다. 상태/종료 명령에도 동일한 `--session`을 지정합니다. 업데이트로 카드 해시가 변경된 경우 기존 세션이 덮어쓰이지 않도록 별도 세션을 사용합니다. 직접 이전 학습 데이터 및 결과를 보관해야 합니다.

# 기존 AI 10시간 자동 학습 (Windows 11)

1. ZIP을 기존 폴더와 별개인 새 폴더에 모두 압축 해제한다.
2. Node.js 24.x가 설치되어 있는지 확인한다. 기존 게임 실행이 가능했다면 추가 설치가 필요 없다. 구버전에서 학습했으면 아래의 **이전 학습 이어받기**를 먼저 진행한다.
3. 전원에 연결하고 Windows 설정 > 시스템 > 전원 및 배터리 > 화면 및 절전에서 전원 연결 시 절전을 '안 함'으로 설정한다. 화면 끄기는 가능하다.
4. `train-ai-10h.cmd` 더블클릭. CPU로 자동으로 대전하므로 브라우저나 GPU가 필요 없고 유료 API/인터넷 연결도 필요 없다. 창을 닫지 않는다.
5. 창의 Elapsed/Remaining/Games/Trials/validated promotions를 확인한다. 별도로 `train-ai-status.cmd`를 열어 저장된 상태를 볼 수 있다.
6. 10시간이 지나면 새 경기 시작을 멈추고 진행 중인 경기까지 마친다. `complete`가 표시된다. `start-game.cmd`를 열고 AI 난이도 25를 고르면 같은 폴더의 학습 데이터를 자동으로 사용한다.

중단 시 Ctrl+C를 한 번 누르고 진행 중인 경기 저장이 끝날 때까지 기다린다. 다시 동일한 파일을 실행하면 총 10시간 중 남은 시간을 학습한다. 갑작스러운 종료에는 마지막 저장 경기까지 복구된다. 완료 후 같은 파일을 다시 실행해도 초기화되지 않는다. 학습 10시간 추가는 명령 프롬프트에서 `node apps/cli/train-ai.ts --hours 20` (누적 20시간).

## 학습 방법

- 19가지 평가 가중치(체력, 치명적 위험, 하수인 가치, 주문/능력, 무기, 손패, 마나, 탈진, 반격 위험 등)를 변형한다.
- 9개 직업과 7가지 덱 스타일(입문, 추천, 공격, 컨트롤, 시너지, 콤보, 전설)을 동일 시드·동일 덱으로 후보 좌석을 교대로 검증한다. 기본 16경기 1차 평가와 독립 시드 32경기 검증을 사용한다. 원래 카드 환경과 가상 변경 환경, 현 챔피언 및 이전 모델에 대한 승률을 각각 확인한다. 1차 56%, 검증 60% 이상뿐 아니라 각 환경 50% 이상, 현 챔피언 검증 58% 이상 및 기본 표본에서 쌍별 유의성 지표(p≤0.10)를 만족해야 승격한다. 검증에는 25단계 탐색과 반격 예측을 사용하되 학습 속도를 위해 노드/반격 후보 수를 제한한다.
- 기존 챔피언은 승격 전 파일로 보존된다. 경기마다 체크포인트와 챔피언을 저장하고, 실제 카드 데이터의 해시별로 분리한다. 카드 밸런스가 달라지면 이전 가중치를 새 환경의 검증 대상으로 먼저 시험하며 원본 카드 파일은 수정하지 않는다.
- 결과 위치: `data/ai/[카드해시]/champion.json`, `checkpoint.json`, `status.txt`.
- CPU 작업자 기본 최대 4개(운영체제에 코어 1개 이상 남김). 온도나 다른 작업이 걱정되면 명령 프롬프트에서 `node apps/cli/train-ai.ts --hours 10 --workers 2`로 시작할 수 있다.
- 1~5단계는 기존 기본 행동 정책, 6~25단계는 점진적으로 증가하는 탐색 예산과 학습된 가중치이다. 25단계는 최대 8행동 연계, 926개 노드, 상대 반격 후보 최대 5개를 고려한다. 온라인은 응답성 확보를 위해 검색 시간을 제한하므로 실제 탐색량은 상황마다 다르다.
- 이는 신경망 학습이 아니라 실제 게임 규칙 기반 자기 대전 진화 최적화다. 학습으로 반드시 승률이 향상되거나 숙련자를 이길 수 있다는 보장은 없다. 승격이 없으면 이전 챔피언을 유지한다.

## 이전 학습 이어받기 (v0.38.0부터)

1. 새 게임 버전을 별도 폴더에 압축 해제한다. 이전 프로젝트 폴더를 삭제하지 않는다.
2. 이전 프로젝트의 학습을 Ctrl+C로 중단하고 저장될 때까지 기다린다(중단하기 어렵다면 현재 챔피언만 옮길 수 있다).
3. 새 폴더에서 `import-ai-data.cmd`를 더블클릭한다. 이전 `card-duel` 폴더를 탐색기에서 명령창으로 끌어 놓고 Enter를 누른다.
4. `IMPORTED ... complete`는 해당 카드 버전의 체크포인트 전체 이식, `champion`은 검증된 가중치만 이식되었다는 뜻이다. `SKIPPED`는 이미 존재하는 결과가 있어 건드리지 않았다는 뜻이다.
5. 새 폴더에서 `train-ai-10h.cmd`를 실행한다. 현재 카드 버전의 기존 모델이 있으면 계속 학습하고, 이전 버전의 호환되는 가중치가 있으면 새 카드 환경에서 1차·독립 검증을 거쳐 자동 승격 여부를 판단한다.
6. `train-ai-status.cmd`는 활성 버전과 다른 버전에 보존된 모델들을 모두 알려 준다. 상태의 `Transfer`는 이번 활성 버전에서 검증한 이식 횟수이다.

학습 가중치는 카드 이름별 저장값이 아닌 보편적 전투 평가 계수이다. 새 카드/밸런스에서 일반화 성능이 유지되는지 실제 대전으로 검증한다. 이전 모델의 게임 수나 승격 수를 새 카드 버전의 실적처럼 더하지 않는다. 실패해도 원본 모델은 남고 같은 가중치를 반복 검증하지 않는다. 이전 버전도 그대로 실행/학습할 수 있다.

고급 명령:

```powershell
node apps/cli/train-ai.ts --list
node apps/cli/train-ai.ts --catalog v0.22.0.json --status
node apps/cli/train-ai.ts --hours 10 --transfer-from v0.22.0.json
node apps/cli/train-ai.ts --hours 10 --no-transfer
```

`--transfer-from`은 해당 버전 또는 64자리 카드 해시를 명시하고, `--no-transfer`은 다음 새 후보의 자동 이식을 건너뛴다. 이미 체크포인트에 있는 시험은 손실 없이 마무리한다. 사용자 밸런스 버전도 같은 원리로 작동한다. 이전 파일과 새 파일은 각 카드 해시 폴더에 따로 보존한다.

## 범용 학습 (v0.39.0부터)

- 카드의 실제 비용, 능력치 및 효과 구조를 보고 전략별 덱을 만든다. 카드별 고정 가치 표가 아니다.
- 약 1/3의 시드에서 일부 덱 카드의 비용, 공격력·생명력, 무기 내구도 또는 피해·치유·강화·드로우·소환량을 ±1 바꾼다. 실제 사용자 카드 JSON에는 아무 변경을 하지 않는다. 변경 버전 역시 원래 스키마로 검사한다.
- 이전 챔피언과 기본 가중치의 리그를 포함하며, 가끔 이전 우수 전략과 현재 모델의 가중치를 혼합한 후 변이시킨다.
- `--validation-pairs`는 독립 검증의 시드 쌍 개수를 변경한다. 기본 16쌍(32경기). 표본이 작은 개발 시험은 통계적으로 충분한 근거가 아니다.
- `--classic-training`은 예전의 추천/입문 덱 중심 시험으로 새 후보를 생성한다. 이미 기록된 진행 중 시험에는 기존 설정을 유지한다.

## CPU 및 기기 실행 (v0.40.0부터)

- `train-ai-quiet.cmd`: 낮은 CPU 사용량 목표, 최대 2개 워커 및 경기 사이 휴식. 발열, 소음 또는 다른 작업이 걱정될 때.
- `train-ai-10h.cmd`: 균형 사용, 최대 4개 워커, 코어와 RAM을 고려해 자동 조절.
- `train-ai-max.cmd`: 최대 8개 워커, CPU 및 여유 메모리가 허용하는 한 높은 처리량. 온도를 직접 확인하고 냉각/전원 관리에 유의한다.
- 세 모드 모두 동일한 카드 해시 별 체크포인트를 이어받는다. 한 버전에 한 번만 실행 가능하다. `--power quiet|balanced|maximum`과 `--workers`를 조합할 수 있다. 경기 중 갑작스런 강제 종료는 최근 약 1–2초 동안의 완료 경기 기록을 잃을 수 있지만, 정상 중단은 진행 중인 경기까지 저장한다.
- `npm run benchmark:device`는 현재 컴퓨터에서 25단계 판단 시간을 비교한다. `npm run benchmark:device -- 9 25 all`은 25단계의 세 성능 설정을 비교한다. 실제 S24 온도/배터리/프레임률의 보장은 아니다.
- 서버 게임의 기기 AI는 공개 가중치만 가져온 뒤 별도의 Worker에서 실행한다. 오프라인 HTML을 새로 생성하면 당시 활성 카드와 현재 챔피언을 함께 포함한다. 기존 HTML은 정적 스냅샷이므로 재생성해야 새 밸런스 및 학습 결과가 적용된다.
# 정책 버전

v0.44의 `backup-ai-data.cmd`는 학습을 멈추지 않고 새 폴더에 현재 시점 체크포인트와 그 안의 동일 챔피언을 보존할 수 있다. 원본은 수정하지 않고, 현재 학습 잠금 파일은 포함하지 않는다. 폴더 이름은 존재하지 않는 새 경로를 지정한다. 복사된 폴더는 `import-ai-data.cmd`의 원본으로 사용할 수 있다. 대상 프로젝트에 동일 카드 해시의 AI 데이터가 이미 있다면 덮어쓰지 않는다.

v0.42부터 25단계 기본 AI는 정책 2를 사용하며 새 범용 학습도 `--policy 2`가 기본이다. 이전 체크포인트의 진행 중인 작업은 기록된 정책(이전 기록에 값이 없으면 정책 1)으로 완주한다. 원래 탐색 방식으로 새 시험을 시작하려면 `--policy 1`을 지정한다. 가중치 형식은 변경되지 않았고 기존 모델은 보존된다. 정책 2의 승률 우월성은 확정되지 않았다.

## 독립 강도 비교 (v0.46 개발)

`npm run benchmark:strength -- 9 18,25 25 2 110 1 current current`는 상대 18/25단계와 목표 25단계를 각각 9개 시드 쌍(18경기)으로 비교한다. 끝의 인수는 목표 정책, 시드 오프셋, 상대 정책, 목표 가중치, 상대 가중치 순서다. 가중치는 `current`, `default` 또는 가져온 챔피언의 64자리 카드 해시를 지정한다. 같은 정책끼리 비교하면 탐색 예산 차이를 분리할 수 있다. 서로 다른 정책의 순위만으로 모델 자체의 우열을 단정하지 않는다.

각 시드 쌍에서는 카드/덱/선공을 고정하고 목표 좌석만 교환한다. 출력에는 카드 해시, 양쪽 가중치 지문, 각 쌍의 점수, 승패 및 쌍 단위 bootstrap 95% 구간이 나타난다. 소표본 구간은 불안정하며, `capped`가 0이 아니면 경기 상한 때문에 결과를 승격 근거로 사용하지 않는다. 평가 명령은 학습 체크포인트나 카드 파일을 변경하지 않는다.

이전 버전 이식 후보는 각 카드 버전의 현재 챔피언을 우선하고, 이후 보관한 이전 챔피언도 버전별로 교차해 검증한다. 같은 가중치 및 이미 거절된 지문은 다시 시험하지 않는다. 어느 후보도 독립 검증 없이 실제 플레이 모델로 채택하지 않는다.

정책 3은 벤치마크에서만 선택할 수 있는 실험 후보다. 이미 턴을 종료한 시뮬레이션 후보에 턴 종료를 또 적용하여 상대 반격 위험을 0으로 잘못 평가할 수 있는 문제를 수정하고, 후보별 반격 표본의 시드 기준을 통일한다. 정책 1·2 및 기존 학습 체크포인트의 동작은 유지한다. `npm run benchmark:strength -- 9 25 25 3 140 2 current current`로 정책 2와 비교하며, 기본 게임 및 학습은 아직 정책 3을 사용하지 않는다.
