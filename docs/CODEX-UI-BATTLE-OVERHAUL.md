## 0. 목표와 불변 조건

목표: 화면은 가로형의 완결된 게임 화면, 덱 편집은 책장처럼 이동, 손패는 즉시 반응, 사용한 카드는 충분히 크게/길게 연출. **플레이어 명령은 애니메이션 중에도 선입력하지만, 여러 행동의 애니메이션은 절대 겹치지 않고 A 완료 → B 시작 → C 시작 순으로 보여준다.**

타사 게임의 정보 구성·UX 원칙은 참고하되 타사 소스/이미지/사운드/브랜드 그래픽을 복사하지 않는다.

변경 금지: 카드 ID·수치·효과, 엔진 판정, 난수, 기존 AI 가중치·체크포인트·훈련 데이터, 25단계 난이도 틀, 저장 형식/기존 세이브, 성장 보상 수치, 기존 백업, 승인되지 않은 서버/PvP 기능. 비공개 데이터와 보이지 않는 카드 정보가 공개 UI에 누출되지 않게 한다. 사용자 승인 없이 main 병합/정식 배포 금지.

## 2. 정보 구조: 최상위 메뉴 3개

메인: **대전 / 덱 만들기 / 카드 도감** 3개 큰 선택지. 각 선택지는 게임 화면 전체를 차지하는 독립 단계.

- 대전: 덱/직업 및 AI 대전 설정, 저장된 경기 이어하기, 슬롯/성장 확인. 기존 기능은 삭제하지 않고 단계/접힌 메뉴로 정리.
- 덱 만들기: 직업 선택 → 새 덱 또는 저장 덱 → 독립 편집기. 편집기 상단은 메인으로 / 덱 이름·직업 / 저장 위주. 사용 빈도가 낮은 추천·공유·백업·고급 설정은 보조 메뉴/팝업으로 이동하되 작동 유지.
- 카드 도감: 보기 전용 전체 화면; 카드 클릭은 덱 추가가 아닌 자세히 보기.
- 현재 DeckWorkspace의 classes/saved/cards/build 중첩 내비게이션을 정돈. 이전/다음/뒤로가기 상태와 편집 중 자동 저장 보존.

### 스크롤 규칙

가로 PC/폰에서 **문서 전체 스크롤 금지, 주요 화면 중첩 세로 스크롤 금지.** 카드책은 페이지 이동; 30장 현재 덱과 저장 덱 목록은 컴팩트 표시 + 페이지 나눔/고정 작업 영역으로 해결. 좁은 화면에서 모든 콘텐츠를 너무 작게 줄여 해결하지 말 것. 화면에 남는 높이를 기준으로 필터를 간략화/접기.

**예외:** 사용자가 연 상세 팝업/도움말/긴 카드 텍스트의 내부 스크롤은 허용. 상세 정보 자체를 자르거나 숨기면 안 된다. 모바일 터치 영역은 44px 이상을 우선, 키보드 포커스/노치 safe-area/화면 회전 지원.

확인 해상도: 1920x1080, 1366x768, 1024x600, 844x390, 667x375. 실물 터치 검증과 Chromium 에뮬레이션은 반드시 구분.

## 3. 책장형 덱 편집/카드 도감

1. 카드책 **오른쪽 바깥 가장자리 또는 ▶ 아이콘 클릭 = 다음 펼침**, 왼쪽 가장자리 또는 ◀ = 이전 펼침. 책장 가장자리 클릭 영역은 카드 클릭/카드 드래그와 분리해 오작동을 방지.
2. 전사 덱 예시: **전사 직업 카드 전부 먼저 → 오른쪽으로 넘기면 공용 카드 전부**. 전사 마지막 펼침에서 ▶ 클릭 시 공용 첫 펼침. 공용 첫 펼침에서 ◀ 클릭 시 전사 마지막 펼침. 그 밖의 직업도 동일 규칙. 첫 장/끝 장에서는 불가능 방향 비활성.
3. 상단 바로가기 [전사 아이콘: 전사 카드 첫 장] [공용 아이콘: 공용 카드 첫 장]. 현재 그룹과 페이지 수를 명확히 표시. 다른 직업에서는 해당 직업 이름과 아이콘으로 변경. **숫자 1,2,3 버튼만으로 페이지를 이동하도록 강제하지 말 것**.
4. 검색, 마나, 종류, 등급, 세트 필터 보존. 정렬은 그룹 내 마나 오름차순, 동률 이름순. 필터 변경 시 페이지 유효성 보장. 기존 카드 자체에 포커스가 있을 때의 방향키 이동과 새 페이지 키보드 이동을 충돌 없이 설계.
5. 기존 12장/펼침은 넓은 데스크톱에서 유지 가능. 짧은 모바일 가로에서는 읽기 불가능한 12장을 억지로 표시하지 말고 컨테이너에 맞춰 자동 페이지당 장수/칼럼 조정. 모든 카드는 정확히 한 번씩 페이지로 접근 가능해야 함. 카드 상세는 호버/길게 누르기/버튼으로 확대 가능.
6. 오른쪽 내 덱 30장, 마나 곡선, 현재 장수, 추가/삭제, 저장/불러오기, 소지 카드 제한 및 카드 중복 제한 모두 유지. 별도 세로 스크롤보다는 컴팩트 목록/페이지 또는 모달 상세.
7. 카드 도감에도 재사용하되 카드 도감은 보기 전용. 직업 전체 보기/선택 직업/공용 구분은 명시적.

## 4. 카드 이름

**카드 이름은 클래식으로만 표시.** 게임 상단 이름 전환 버튼 제거. 전투/손패/덱/도감/로그/안내문에 같은 표시 원칙 적용. 기존 ID·저장 데이터·자체 이름 원본은 유지(삭제 금지). REFERENCE_CARDS에 없는 매핑은 감사 리스트로 보고하고 임의 이름을 지어내지 않는다. 매핑 누락 시 기존 이름 임시 사용 사실을 보고.

## 5. 손패 조작

- PC에서 손패 카드 마우스 진입 시 거의 즉시 확대 시작, **약 0.1초 내 확대 완료**. 카드가 약간 위로 올라오고 양옆 손패를 좌우로 부드럽게 밀어낸다(약 0.10~0.15초). 마우스를 떼면 부드럽게 복귀.
- 손패 확대를 전역 1000ms 상세 호버 딜레이와 분리. 기존 카드 도감 툴팁은 손패 속도 변경에 연동하지 말 것.
- 호버 중 카드 hitbox가 움직여 미세한 커서 움직임에 카드 선택이 진동하지 않게. 손패 1~10장, 왼쪽/오른쪽 끝, 좁은 창, 빠른 마우스 이동, 포커스, 탭, 드래그, reduced-motion 검증.
- **전투 중간의 상시 고정 카드 상세 영역은 제거/접음.** 손패 호버/선택/길게 누르기/별도 상세 팝업으로 같은 정보 제공. 카드 설명·키워드/부가설명 보존.

## 6. 카드 공개와 길고 명확한 연출

- 내가 낸 카드와 AI/상대가 낸 카드 **모두 크게 보여준 뒤** 실제 효과/소환 시각화. 상대 비공개 손패/비밀 카드는 승인된 공개 이벤트가 발생하기 전까지 실체를 보이지 않게 한다.
- 기본 normal 일반 소환 총 길이는 약 **2000ms**. 카드 등장/확대 → 마법진·소환 이펙트 → 전장 착지/정착. 같은 행동 내부의 여러 효과는 자연스럽게 연결하되 **다른 행동의 연출과는 겹치지 않는다.**
- 공격/주문/사망의 시간은 해당 효과에 맞게 조절; 모든 소행동을 무조건 2초 고정하지 않음. fast/instant/reduced-motion·대사/효과음/FX 성능 예산 보존.
- 엔진이 승인하지 않은 행동은 어떤 화려한 카드 사용 연출로도 표시하지 말 것.

## 7. 핵심: 입력 선입력 큐 + 시각 직렬 큐

정확한 사용자 요구는 다음 세 조건을 **동시에** 만족하는 것이다.
A. **첫 소환 연출이 재생 중이어도 두 번째 카드/공격/턴 종료를 입력할 수 있음.**
B. **게임 판정은 승인 상태 기준으로 명령을 순서대로 검증.**
C. **시각적으로는 A 연출이 완전히 끝난 다음 B, 그다음 C. 연출 동시재생 없음.**

### 명령 큐

- Battle.tsx 입력 경로와 로컬 Worker/서버 액션을 조사해 별도 pending intents FIFO 도입/확장. 인스턴스 ID, 목적, 타겟, 보드 위치 등의 의도를 저장; 재진입/중복 입력 방지. UI에는 '예약 1/2/3' 같은 상태와 아직 미확정 예약 취소를 보여줌. 과다 적체 방지(예: 최대 4개).
- **권위 상태(authoritative latest state)**와 **화면 표시 상태(visible playback state)**를 구분. 한 번에 미확정 액션 하나만 워커/서버에 보내고 Ack+revision 이후 다음 의도를 최신 승인 상태에서 재검증: 마나, 손패 보유, 같은 인스턴스, 대상 생존, 공격권, 턴, 전장 자리/선택 분기.
- 첫 행동 후 다음 행동이 불가능하면 해당 예약은 무효 처리하며 이유 표시. 예약된 동일 카드를 두 번 제출하거나 오래된 revision의 action을 서버에 보내지 말 것. 아직 공개되지 않은 미래 드로우 카드의 액션은 미리 예약 불가능.
- **턴 종료도 FIFO 예약**: 앞서 예약된 행동들이 확인된 뒤 실행. 턴 변경/대전 종료/리셋/연결 끊김/재시작 시 예약 처리 정책을 테스트로 정의하고 안전하게 비움.
- **기존 저장에는 승인된 게임 상태만 남긴다.** UI 명령 예약/FX 큐를 기존 저장 스키마에 넣거나 저장·백업을 오염시키지 말 것. 이어하기는 권위 상태에서 재개, 미확정 의도는 폐기.
- 빠른 탭/더블클릭, 취소 vs Ack, 타겟 사라짐, 연결 복원, worker crash, save retry, 하나의 탭/다른 탭 경쟁까지 테스트.

### 연출 큐

- 기존 PlaybackTimeline을 재사용/수정해 승인된 연속 revision마다 before/after/action FX를 순차 담는다.
- **하나의 연출이 끝나면 다음 시작.** A(0~2초), B(2~4초), C(4~6초) 예시. 입력은 0, 0.2, 0.4초에 진행 가능. 실제 실행·확정/엔진 통신 타이밍은 비동기일 수 있으며 임의로 결과를 보여주지 않는다.
- 미래에 승인된 결과도 이전 연출이 끝나기 전까지 화면에 미리 노출하지 않는다. 전투 로그도 해당 연출이 표시되는 순서에 맞춰 나타난다. 오디오/파티클/카드 확대 등 **행동 간 비중첩** 확인.
- 브라우저 백그라운드/비연속 revision/재접속 시 애니메이션을 생략하고 승인된 최신 상태로 안전하게 스냅할 수 있다. 단, 허위 액션 재생/허위 로그 생성 금지. 적체 시 적절한 입력 역압 사용, 무검증 액션 삭제/화면 상태 점프 금지.
- 사람·기기 AI 모두 동일 원칙 적용. 사용 중 UI 조작 불능 플래그/터치 차단이 있으면 안전하게 선입력을 허용하도록 수정.

### 최소 큐 테스트

- 유효한 A, B, C를 짧은 간격으로 선입력: 모두 승인되면 애니메이션이 겹치지 않는지 확인.
- A가 마나를 소비해 B 불가: B만 안전 거부. A가 타깃을 제거한 경우 B 공격을 허위 실행하지 않음.
- 같은 손패 인스턴스 중복 예약, 멀리건/선택 생성, 선입력 턴 종료, 유효성 실패, 판정 실패, 연결 끊김, 일시 저장 실패, 이어하기, 경기 완료.
- 상대 AI의 연속 행동과 로그 타이밍, 단일 이펙트 layer의 새 큐 전환 중 이전 FX 잔존 없음.

## 8. 왼쪽 아이콘 전투 기록

- 메인 전투판 왼쪽에 최근 행동을 **텍스트 문장 대신 카드 그림 아이콘 중심**으로 수직 표시. 소환(카드 그림), 공격(검/충돌), 주문, 회복, 사망/변신 등 실제 공개된 결과를 반영.
- 호버/키보드 포커스로 크게 확대해 카드 이미지, 공격자 → 상대 하수인/영웅, 양쪽 피해·체력/방어도, 소환/사망 등 관계를 이미지·기호로 보여줌. 모바일에서는 탭하여 상세. 접근성 대체 텍스트와 상황 설명 유지.
- existing impact history의 승인 전후 revision + 공개 events를 데이터 근거로 재사용. 적의 비공개 손패·비밀 카드 정체 누출 금지.
- 좁은 폰 가로에서 왼쪽 로그가 전투판/턴 종료 버튼을 가리지 않도록 접힌 아이콘 레일/팝업 우선.

## 9. Codex 구현 순서

1. 메인 3메뉴 + 스크롤 없는 독립 페이지, 저장/대전 경로 회귀.
2. 책장 양쪽 클릭, 직업→공용, 탭·필터, 도감 및 덱 목록 페이지.
3. 클래식 이름 단일화 + 손패 0.1초 확대/이웃 카드 밀기 + 중앙 카드 상세 제거.
4. 명령 FIFO 선입력 + 승인 상태/시각 상태 분리. **핵심 로직 테스트 먼저**.
5. 내·상대 2초 기본 소환/큰 카드 공개, **연출 직렬** + 즉시/빠름 모드.
6. 왼쪽 아이콘 로그, 호버 확대 및 전체 브라우저/저장/PWA 회귀.

단계별 구현 → 테스트 → 작은 Git 커밋 → docs/PROGRESS.md/HANDOFF.md 기록 → 다음 단계. 문제가 있으면 삭제/무시하지 말고 원인/한계/미완료 범위 명시.
