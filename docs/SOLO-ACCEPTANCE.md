# 설치형 솔로 실기 확인 순서

**현재는 개발 후보입니다.** 자동 실행 검사와 실제 PC/갤럭시 설치 시험을 구분합니다. 실기 확인 전에는 중요한 기존 기록을 삭제하지 않습니다.

## Windows PC (고정 주소)

1. ZIP 압축을 완전히 풉니다. `dist/solo-app/index.html`과 `start-offline-app.cmd`를 확인합니다. Node.js 24가 설치된 PC에서 시작 파일을 실행합니다.
2. 평소 사용할 브라우저 프로필에서 `http://127.0.0.1:4179/`를 엽니다. `localhost`, 다른 포트, 시크릿 창, 다른 브라우저, 파일 직접 실행은 서로 다른 저장 공간입니다. 기존 파일 버전의 성장/덱 백업을 새 주소에 복원해야 합니다.
3. 브론즈 5 유저 모드와 25랭크, 컬렉션, 퀘스트 순서를 확인합니다. 개발자 모드에서만 전체 카드 연습과 임의 랭크 시험이 가능하고 보상이 없음을 확인합니다.
4. 유저 모드에서 조건에 맞는 랭크 경기를 완료하고 XP·전적·해금 변화를 기록합니다. 같은 결과를 다시 열어도 동일 보상이 중복 지급되지 않아야 합니다. 조기 항복은 XP/퀘스트 보상 대상이 아닙니다.
5. 새 랭크 경기 시작 후 자동 저장 표시를 확인하고 창을 닫습니다. 같은 주소에서 이어하기로 진행 상황과 카드 상태를 확인합니다. 완료한 경기의 성장과 현재 경기 저장은 서로 다릅니다.
6. 오프라인 앱 준비 완료를 확인한 후 지원 브라우저의 앱 설치 기능을 이용합니다. 기기 저장 보호 요청을 선택하고 승인 상태를 확인합니다. 인터넷을 끄고 로컬 실행기를 종료한 뒤 캐시된 앱에서 이어하기를 시험합니다. 실패 시 인터넷/실행기를 복구하며, 기존 브라우저 데이터를 지우지 않습니다.
7. 성장 백업 JSON과 저장 덱 JSON을 별도로 내려받습니다. 파일로 보관하고 새 브라우저 프로필에서 복구 시험을 합니다. 성장 복원은 아직 진행하지 않은 기록에서만 가능하며, 저장 덱은 기존 덱을 덮어쓰지 않고 추가됩니다. 성장 파일에는 진행 중인 경기나 저장 덱이 포함되지 않습니다.
8. 로비에서 저장 슬롯 2를 선택합니다. 처음 사용한다면 브론즈 5, XP 0, 진행 중 경기 없음이 표시되어야 합니다. 새 경기 저장 후 슬롯 1로 돌아가 기존 XP·보유 카드·덱·이전 경기가 남아 있는지 확인합니다. 슬롯 2를 다시 선택하고 새로고침해 독립 기록과 선택 상태가 유지되는지 확인합니다. 슬롯 3도 동일하게 검사합니다. 서로 다른 슬롯을 두 탭에서 열어도 한쪽 저장이 다른 쪽에 반영되면 안 됩니다. 슬롯 전환은 대전 로비에서만 가능합니다. 슬롯 삭제/초기화 기능은 제공하지 않습니다.
9. 슬롯 선택 전 각 슬롯 미리보기의 랭크·XP·이어할 경기 유무가 실제 저장과 일치하는지 확인합니다. 미사용 슬롯은 새로 시작 버튼으로 열 수 있지만 기록이 있는 슬롯은 초기화하지 않습니다. 다른 카드 해시에만 경기 기록이 있으면 이전 버전 경기 있음으로 표시합니다. 브라우저가 저장소 조회를 거절하면 빈 슬롯으로 판단하지 않습니다.
   v0.184부터 모바일 앱을 빠르게 다른 화면으로 전환했다 돌아와도 같은 미리보기 작업이 중복 시작되거나 계속 취소되어 확인 중으로 남아서는 안 됩니다. 배경에서는 불필요한 미리보기 조회만 멈추고, 돌아오면 최신 슬롯 정보를 다시 읽어야 합니다.
10. 성장+덱 통합 백업을 다운로드합니다. 백업은 진행 중인 경기 및 미저장 편집 덱을 포함하지 않습니다. 다른 미진행 슬롯에서 성장 복원으로 통합 파일을 한 번 선택합니다. 확인 창에 원본/대상 슬롯과 추가 예정 덱 수가 나오며, 성장 반영 뒤 저장 덱도 자동 추가하는지 확인합니다. 기존 성장 진행이 있는 슬롯은 성장 복원 거절, 기존 저장 덱은 별도 이름으로 보존, 잘못된 성장/덱 형식이나 알려진 덱 용량 초과는 복원 전에 거절합니다. 두 저장소 사이에 공통 트랜잭션은 없으므로 성장 복원 후 덱 저장만 실패한 경우 동일 파일을 덱 리스트에서 재시도합니다.

## 패치 적용

- 업그레이드 전에 성장/덱을 백업합니다. 카드 데이터가 바뀌는 버전으로 이동하기 전에는 진행 중인 랭크 경기를 완료합니다(저장 경기의 카드 해시가 다른 버전 간 이전은 아직 지원하지 않습니다). 미완료 이전 경기 발견 시 새 랭크 시작을 거절하며 기록을 삭제하지 않습니다. 기존 주소에서 이전 릴리스를 다시 실행해 경기를 끝낸 후 최신 버전을 적용합니다. 다른 슬롯은 별도로 이용할 수 있습니다. 같은 해시의 UI 변경 패치에서는 이어하기와 XP가 유지되는지 검사합니다.
- 새 ZIP을 별도 폴더에 풀고 기존 로컬 실행기를 종료한 다음 새 실행기를 같은 주소로 시작합니다. 게임 앱 상단 버전/새 버전 준비 상태를 확인합니다. 필요한 경우 모든 게임 창을 닫고 재실행합니다.
- 실행기는 시작 시 전체 배포 파일의 무결성을 확인합니다. `node apps/cli/serve-solo-app.mjs --verify`로 별도의 패키지 확인도 가능하며, 복사 중인 혼합 릴리스는 실행하지 않습니다. 앱에서 패치 확인 버튼을 눌러 최신 여부/검증 중/준비 완료/오프라인 실패 안내를 확인합니다. 진행 중 경기를 저장하고 모든 게임 창을 닫기 전에는 새 버전을 강제 적용하지 않습니다.
- 업데이트 전후 XP, 랭크, 보유 카드, 전적, 저장 덱을 비교합니다. 기존 파일과 백업을 지우지 않습니다. 새 버전의 해시 검사가 실패하면 기존 앱은 유지됩니다.
- v0.174부터 활성화가 확인된 직전 릴리스 캐시만 정리합니다. 패치가 여러 개 겹쳐도 설치 중인 다른 캐시를 지우지 않으며 이전 방식의 캐시는 확실히 식별할 수 없으면 유지합니다. 같은 릴리스의 정상 캐시 파일은 해시를 다시 확인해 오프라인 재설치에 재사용하고, 손상된 파일만 같은 해시의 원본으로 복구합니다. 브라우저 사이트 데이터/경기 저장소는 삭제하지 않습니다.
- v0.177부터 설치형 `dist/solo-app/index.html`은 `game.js`와 카드 그림을 포함한 `game.css`를 별도 제공하지만 두 파일 모두 나머지 자산과 함께 설치 전 SHA-256 검증·오프라인 캐시 대상입니다. 압축 해제 후 두 파일이 빠진 상태에서는 실행되지 않아야 합니다. 예전 5개 파일 설치 패키지와 새 7개 파일 패키지를 같은 로컬 주소에서 업그레이드·롤백할 수 있는지 검사합니다. `solo-offline.html` 직접 실행판은 기존처럼 모든 게임 코드와 그림이 포함된 하나의 파일입니다. 업데이트 중 브라우저의 사이트 데이터는 삭제하지 않습니다.
- v0.178부터 첫 설치 시 `오프라인 앱 설치 중` 상태를 확인합니다. 최초 방문 화면에서는 캐시 준비 중에도 게임을 계속 플레이할 수 있어야 합니다. 네트워크 차단/저장 용량 초과 등으로 설치가 실패하면 오프라인 재실행을 보장하지 않는다는 안내가 표시돼야 합니다. 이전 버전 패치 실패 시에는 기존 설치판 유지, 새 패치가 대기하는 동안에는 `준비 완료` 안내가 다른 초기화 메시지로 바뀌지 않는지도 확인합니다.
- v0.179부터 브라우저 저장 보호 상태 확인이 늦게 끝나더라도 이후 사용자 클릭으로 확인된 최신 승인/실패 메시지를 덮어쓰지 않아야 합니다. 보호 미승인은 저장 실패가 아니며, 사용자 백업은 계속 권장합니다. 승인 요청 중 버튼을 중복 누를 수 없어야 합니다.
- v0.180부터 앱 서비스 워커는 사용 중 처음 접근하는 캐시의 실제 내용을 릴리스 해시와 비교합니다. 파일이 손상된 경우 이를 게임 코드/스타일로 그대로 제공하면 안 됩니다. 원본을 읽을 수 있으면 같은 버전으로 복구하고, 완전 오프라인이면 파일 누락/복구 불가 메시지를 표시하며 저장된 경기나 정상적인 다른 파일을 삭제하지 않아야 합니다.
- v0.181부터 첫 설치 또는 검증 중인 패치의 진행 안내에 `캐시 파일 N/7 확인`이 표시될 수 있습니다. 일러스트가 큰 파일은 개수와 실제 다운로드 비율이 다르므로 퍼센트로 간주하면 안 됩니다. 설치가 끝난 뒤 늦게 도착한 메시지나 다른 앱 버전의 진행 정보로 `준비 완료`/`패치 준비 완료` 상태가 덮어쓰이지 않아야 합니다.
- v0.182부터 게임 JS·스타일·설치 등록 파일이 로드되지 않는 상황에서는 초기 문서 자체가 경고를 띄웁니다. 로컬 실행기를 다시 켜고 같은 버전 자산으로 복구한 뒤 새로고침하라는 안내가 보여야 하며, 오류가 있는 페이지를 `오프라인 앱 준비 완료`라고 잘못 표시하면 안 됩니다. 브라우저 사이트 데이터나 사용자 저장 기록을 삭제하지 않습니다.
- v0.183부터 보안 출처/서비스 워커를 지원하지 않는 브라우저에는 `오프라인 설치 미지원`이 표시됩니다. 이 환경에서 게임 화면이 보인다고 해서 오프라인 재실행이 보장된 것으로 해석하지 마세요. 이미 게임 JS나 CSS 로딩에 실패한 경우에는 파일 복구 안내가 우선합니다.

## 일시적인 저장 오류·여러 탭 검사 (v0.105 이상)

- 테스트용 슬롯에서 같은 주소/브라우저 프로필의 탭 두 개를 엽니다. 한 탭에서 새 이름의 덱을 저장하고 다른 탭에서 다른 이름의 덱을 저장합니다. 두 덱 모두 남아야 합니다. 한 탭에서 동일한 덱을 수정한 뒤 다른 탭의 오래된 편집 상태로 덮어쓰기·삭제하면 다시 확인하라는 안내가 나오고 최신 기록이 유지되어야 합니다.
- 지원 브라우저는 Web Locks를 사용해 현재 출처의 덱 저장·삭제·가져오기를 직렬 처리합니다. 잠금이 오래 지연되면 저장을 강행하지 않고 재시도를 요청합니다. 미지원 브라우저에서는 v0.104의 최신 목록 및 대상 검사로 대체하므로 정확히 동시 실행되는 다중 탭 작업은 피합니다. 이전 버전의 열린 탭은 잠금을 공유하지 않으므로 패치 전 모든 탭을 닫습니다.
- 테스트용 경기에서 저장소 연결 문제를 재현할 수 있는 환경이라면 자동 저장 실패 후 연결 복구 시 `저장 재시도 후 나가기`로 경기와 성장 보상을 저장하는지 확인합니다. 다른 탭이 같은 경기 소유권을 가져갔다면 이전 탭의 저장은 거절되어야 합니다. 중요한 사용자 데이터를 지우거나 손상시키지 않습니다.

## 모바일 추후 시험

현재 로컬 실행기는 PC 내부 전용이며 스마트폰에서 PC의 127.0.0.1로 연결되지 않습니다. 모바일 PWA에는 안전한 HTTPS 출처가 필요하고 APK는 별도 빌드/서명이 필요합니다. 실기에서는 Galaxy S24 기준 393×852 전후 화면에서 터치 조작, 자동 저장, 기기 네트워크 차단 후 재실행, 1~25 AI 지연, 장시간 플레이, 앱 업데이트 및 데이터 보존을 시험합니다. PC/모바일 진행 실시간 동기화 및 사람과의 온라인 대전은 계정 서버 연결이 별도 필요합니다.

- v0.185부터 앱을 배경에 두면 전투 턴 시간과 재접속 카운트다운의 화면 갱신을 멈추고, 복귀 시 실제 마감 시각으로 즉시 숫자를 복구합니다. 배경 중에도 엔진의 원래 턴 제한이나 저장 기능이 일시 정지한 것으로 해석하지 말아야 합니다. 화면 복귀·재접속에서 숫자 중복/음수 표시가 없는지 실기 확인합니다.

## v0.198~0.203 후보 모바일/저장소 중점 실기 회귀
