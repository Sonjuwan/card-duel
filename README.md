# Card Duel v0.309.0 · 전투 연출과 보상의 길

카드 버전이 바뀐 뒤 같은 슬롯에 이전 카드 버전의 진행 중 랭크가 남아 있으면 새 랭크 대전을 시작하지 않습니다. 이전 버전의 기록은 삭제하지 않으며 기존 주소에서 이전 릴리스로 복귀해 해당 경기를 완료한 후 최신 릴리스를 다시 적용합니다. 다른 슬롯은 독립적으로 이용할 수 있습니다. 기존 성장+덱 백업은 가능합니다. 카드 수치 변경 없는 UI 패치는 같은 카드 해시의 저장 게임을 그대로 읽습니다.

**성장+덱 통합 백업:** 유저 모드의 성장 기록 백업 메뉴에서 현재 슬롯의 XP·랭크·해금 카드·퀘스트·랭크 전적과 저장 완료 덱을 하나의 JSON으로 내려받을 수 있습니다. 새 기기/미진행 슬롯의 성장 복원 메뉴에서 통합 파일을 한 번 선택하면 성장 복원 후 덱도 자동 추가합니다. 기존 성장과 덱을 덮어쓰지 않습니다. 두 저장소의 기록은 별도이므로 덱 추가만 실패하면 덱 리스트에서 같은 파일로 재시도합니다. 아직 저장하지 않은 편집 덱과 진행 중인 경기·연습 전적은 포함하지 않습니다. `docs/PWA-PAGE.md`에 PC 실행 및 추후 모바일 정적 페이지 연결을 구분했습니다.

저장 슬롯 선택 화면은 각 슬롯의 랭크·XP·이어할 경기 유무를 미리 보여 줍니다. 새로 시작 버튼은 성장/경기/덱 등 기록이 없는 것으로 확인된 슬롯에만 표시되며, 기존 데이터를 삭제하는 기능은 아닙니다. 조회 오류는 빈 슬롯으로 표시하지 않습니다. 이전 카드 버전 경기의 존재도 표시합니다. 다른 슬롯의 성장/경기 기록을 수정하지 않는 읽기 전용 조회입니다.

**현재 우선순위: PWA 웹앱 + 로컬 저장.** 첫 번째 저장 슬롯은 기존 버전의 저장 주소 및 키를 그대로 사용합니다. 로비에서 2·3번 슬롯을 선택하면 기존 기록을 지우지 않고 별개의 브론즈 5/XP 0 기록으로 시작할 수 있습니다(이미 사용한 슬롯은 기존 기록을 이어갑니다). 각 슬롯의 성장·경기·편집 덱·저장 덱·연습 기록·설정은 독립적으로 저장되며, 선택한 슬롯에서 성장/덱 백업을 내보내고 복원합니다. 서로 다른 기기나 출처의 데이터는 자동 공유하지 않습니다. 외부 서버 및 APK 제작은 후순위입니다. 실기 검증은 `docs/SOLO-ACCEPTANCE.md` 참조.

개발자 모드에만 원래 최약/최강 AI 정책을 결정적으로 혼합하는 25단계 실험을 추가했습니다. 실제 유저 랭크에는 적용하지 않고 보상도 지급하지 않습니다. 200경기 비교에서 구간별 차이는 관찰했지만 인접한 모든 단계의 차이가 검증되지 않았습니다. `docs/AI-DIFFICULTY-AUDIT.md` 참조.

**Android APK 제작 후보 소스:** 앱 고정 저장 주소, 외부 네트워크 권한 없는 내장 WebView, Android 시스템 문서 선택 기반의 성장/덱 백업, Android SDK만 사용하는 빌드·서명·검증 스크립트를 추가했습니다. `docs/ANDROID-APK.md`에 PC의 SDK 준비 및 개인 키로 APK를 만드는 방법이 있습니다. 현재 SDK가 없어 Android Activity 컴파일/서명/설치 시험은 미착수이며 APK는 제공하지 않습니다. 기존 PC 실행 방식과 온라인 코드는 유지합니다.

오프라인 앱에 현재 버전 표시, 사용자 요청으로 브라우저 저장 공간 보호 승인 확인, 캐시 파일 유실 시 같은 릴리스 파일의 해시 검증 복구를 추가했습니다. 저장 보호를 승인받아도 브라우저 데이터 삭제, 기기 고장에 대비한 별도 백업이 필요합니다. 실제 PC/모바일 설치·업데이트 시험 순서는 `docs/SOLO-ACCEPTANCE.md`에 있습니다. 카드 데이터가 바뀌는 패치 전에는 랭크 경기를 먼저 완료하세요(서로 다른 카드 해시의 진행 경기 이전은 미지원).

**PC 고정 주소 오프라인 앱 (실기 확인 전 개발 후보):** 완전한 배포 ZIP을 풀고 Node.js 24가 설치된 Windows에서 `start-offline-app.cmd`를 실행한 뒤 항상 `http://127.0.0.1:4179/`를 같은 브라우저 프로필로 엽니다. 제공된 `dist/solo-app/`이 있으면 npm 설치 또는 외부 서버 연결 없이 실행할 수 있습니다. 최초 캐시 완료 후 지원 브라우저에서 앱 설치를 시도할 수 있습니다. 새 버전에서는 동일 주소로 실행하고 경기 저장 후 모든 앱 창을 닫았다가 다시 열어 적용합니다. 저장 기록은 해당 브라우저의 주소에 연결되므로 기존 `solo-offline.html` 파일에서 이동할 때는 성장 및 덱 백업을 먼저 내보내고 새 주소에 복원하세요. 브라우저 데이터 삭제 시 기록이 사라질 수 있으므로 주기적 백업을 권장합니다. PC 실행 주소는 기기 내부에만 열리며 모바일 기기에서는 접속할 수 없습니다. 모바일은 추후 HTTPS PWA 배포 또는 APK가 필요합니다. 실제 Windows/Android 설치와 저장 복원은 아직 실기 확인 전입니다.

개발용: `npm run build:solo-app`으로 독립 HTML 및 설치 패키지를 생성하고 `npm run solo:serve`로 고정 주소에서 실행합니다. 설치 패키지의 작은 `index.html`은 `game.js`와 그림을 포함한 `game.css`를 별도로 읽으며, 세 파일 모두 전체 해시 검증·오프라인 캐시에 포함됩니다. 파일 하나인 `solo-offline.html`도 그대로 생성됩니다. `npm run test:solo-app`은 실제 파일과 HTTP 제공, 구형 5파일/신형 7파일 간 업데이트·롤백, 캐시 검증/오프라인 응답/손상 패치 차단을 검사합니다. `npm run test:solo-app-browser`는 Chromium에서 휴대폰 크기로 네트워크 없는 랭크 이어하기를 검사하는 실기용 시험입니다. 서비스 워커는 동일 경로의 완전한 새 버전을 검증한 뒤 기존 창 종료 시 적용하며 IndexedDB와 localStorage에 손대지 않습니다.

오프라인 유저 모드에서 25랭크 및 카드 전력별 해금 현황, 382종 카드 검색·필터·페이지, 다음 해금 XP, 9직업 순환 퀘스트, 최근 30경기 전적을 확인할 수 있습니다. 랭크 대전은 개발자용 절전 설정과 독립적으로 자동 탐색을 사용합니다. 카드 능력치와 AI 학습 데이터는 그대로 유지합니다.

공개 Supabase 서버는 SQL 001~006과 실제 서버 역할의 RLS 우회 권한까지 읽기 전용으로 확인해야 시작한다. 기존 계정 행과 게임 보상에는 변경을 가하지 않는다.

실제 SQLite 계정 원장에 합성 경기 결과 144개를 기록하며 25랭크·9직업 순서 퀘스트·382장 해금·기기 세션·DB 재시작·오래된 경기 중복 정산 및 후속 XP 설정 변경 시 보유 카드 유지까지 검사한다. 승률은 가정이며 AI 실전 승률 측정이 아니다.

9직업 영웅 능력과 성기사·주술사 보유 카드 PvP를 함께 실행하는 로컬 부하 시험을 제공한다. 소환물이 손으로 되돌아간 뒤 AI가 다시 플레이하는 경우도 검증한다.

신규·복원 경기와 AI 작업 스레드가 동일한 영웅 능력 생성 하수인 정의를 사용한다. 서버는 불변 카드 정의를 여러 경기에서 공유하되 개별 경기 상태와 추후 카드 패치는 분리한다.

성장 데이터의 25랭크, 카드 XP 순서, 직업 퀘스트 규칙과 개발자 운영 응답 필드를 검증한다. 최신 조회가 아닐 때 성장 정보와 배포 준비 근거로 사용하지 않는다.

다른 기기의 활성 경기와 계정 최신 진행을 확인하는 동안 신규 계정 대전을 잠시 차단한다. 이전 조회나 잘못된 응답은 대기 상태로 취급하지 않으며, 확인된 활성 경기의 이어하기 버튼은 성장 정보 조회와 독립적으로 제공한다.

재시작 중 유효한 저장 경기 수가 서버 용량을 초과하면 일부를 버리지 않고 시작을 중단한다. 중복 저장 방·활성 계정·정산 데이터 및 잘못된 보상 형식도 검사한다. 만료된 경기와 카드 버전이 호환되지 않는 경기의 기존 처리 규칙은 유지한다.

개발자 성장 설정과 배포 사전 검사는 25랭크 × 9직업 × 4시드의 900개 생성 AI 덱을 비교한다. 30장 전력 합의 증가/동일/감소 및 AI 지능의 실제 탐색 설정을 표시한다. 실제 승률이나 카드 능력치 밸런스는 측정하지 않는다.

클라우드 저장 경기 복원은 여러 페이지를 끝까지 읽고 중복/잘못된 저장 레코드를 검사한다. 이메일 확인 전 가입 응답은 실제 인증 서버의 사용자 객체 형식도 지원하며 잘못된 저장소 응답은 로그인 만료로 오인하지 않는다.

게임 초기 접속은 최신 카드 데이터를 25초 안에 확인하고 실패 시 다시 불러오기 버튼을 제공한다. 버전이나 카드 해시 불일치 시 자동 새로고침은 탭당 한 번만 허용하며, 이후에는 온라인 대전을 차단하고 직접 최신 화면을 불러오도록 한다.

공개 게임 페이지의 WebSocket 허용 출처를 정확한 게임 서버로 제한하고, HTTPS 강제 및 동일 출처 자산 보호를 적용했다. 외부 요청·쿠키·본문·반복 로그인 차단과 실제 배포 보안 헤더 검사도 추가했다.

계정 네트워크 요청에 25초 제한과 이전 조회 취소를 적용했다. 일시 연결 실패는 로그인 만료와 구분하고, 응답이 유실된 저장/인증 변경은 반영 여부를 확인하도록 안내한다.

점검 중 신규 계정 대전뿐 아니라 서버 덱 변경 및 비밀번호 변경·재설정을 잠시 막고, 이미 접수한 계정 변경과 기존 경기의 정산이 모두 끝나야 배포 준비가 완료된다. 로그인·가입 및 로컬 편집은 계속 가능하다.

계정 패널을 접은 상태에서도 랭크/XP를 확인하고 동기화는 계속된다. 25개 카드 전력별 해금 현황, 게임·퀘스트 XP 안내, 개발자 운영 상태의 최근 조회 시각 및 stale 상태 경고를 추가했다.

실제 운영 엔트리의 격리된 소스 사본을 구버전→새 카드/성장 패치→구버전으로 3회 실행하여 기존 계정 진행과 패치로 지급된 카드의 영구 보존을 검증한다. 원본 카드와 성장 설정은 수정하지 않는다.

실제 배포 후 `online:acceptance -- <HTTPS 출처> --disposable-test-accounts`로 신규 시험용 유저 두 명과 세 독립 로그인 세션의 덱 동기화, 랭크 AI 이어하기·XP, 보유 PvP 정산을 확인한다. 기존 진행 계정과 점검 중 서버는 거절한다. 실제 시험 기록은 남으므로 폐기 가능한 계정으로만 사용한다.

PC와 모바일에서 서로 다른 덱을 동시에 저장해도 변경분이 합쳐진다. 같은 이름의 덱이 다른 기기에서 바뀌면 기존 저장본과 현재 편집 초안을 보호하고 다시 확인하도록 안내한다.

`online:smoke -- <서버 출처> --ready`는 테스트 개발자 계정만 사용하며, 점검 모드 저장과 활성 경기·미정산·저장 오류가 없는지 최종 확인한다. 배포나 점검 상태를 직접 변경하지 않는다.

배포 승인 검사는 버전 번호뿐 아니라 승인 소스의 카드·성장 해시 및 배포용 AI 챔피언 가중치와 세대를 직접 비교한다.

PC·모바일의 같은 Wi-Fi 계정 연동 시험은 `start-lan-test.cmd`로 실행한다. 운영 계정과 분리된 로컬 테스트 DB를 사용하고 실제 이메일·비밀번호는 사용하지 않는다.

클라우드 이메일 확인이 필요한 가입은 로그인 완료가 아닌 대기 상태로 표시한다. 이메일 확인 전에는 신규 게임 세션이나 진행 프로필을 만들지 않는다.

장기 계정 대전 연결의 세션 및 개발자 권한도 주기적으로 재검증한다. 외부에서 만료된 권한은 다음 재확인 행동에서 기존 경기 좌석을 해제하지만, 유효한 같은 계정으로 이어할 수 있다.

실제 로컬 운영 엔트리 서버를 시작·종료·재실행해 계정 진행과 점검 상태, 저장 랭크 경기를 보존하는 시험을 `npm run test:online-smoke`에 포함했다.

기기 AI 대전 중에는 서버 버전 변경으로 경기를 중단하지 않는다. 최신 버전 안내를 표시하고 로비로 돌아갈 때 자동 적용하며, 카드 설정이 달라진 경우 저장 경기 호환 제한을 안내한다.

실제 배포한 HTTPS 주소 점검은 `npm run online:smoke -- <서버 출처>`로 수행한다. 별도 테스트 계정의 두 세션 검증과 실제 PC/모바일 출시 절차는 [배포 승인 체크리스트](docs/RELEASE_ACCEPTANCE.md)를 참조한다.

같은 계정의 다른 기기에 진행 또는 대기 중인 계정 대전이 있다면 자동 표시한다. 기존 게임을 이어할 수 있으며 확인된 활성 방이 있으면 신규 계정 대전 버튼을 차단한다.

기존 AI 학습 데이터와 별도로 검증된 두 챔피언을 Git 배포용으로 보존했다. 서버 및 오프라인 빌드는 정확히 일치하는 카드 해시의 모델만 사용하며 개발자 상태에서 실제 선택 모델을 확인할 수 있다. `npm run ai:release`는 현재 카드 버전 챔피언을 배포용으로 갱신한다.

계정 보유 카드만으로 현재 직업 또는 퀘스트 직업의 성장 추천 덱을 만들 수 있다. 카드 컬렉션의 전력 단계/이름 필터, 다음 해금 XP 진행률, 성장 설정 백업의 안전한 초안 복원도 추가했다.

개발자 점검 모드는 새 계정 랭크/PvP/시험 경기를 차단하고 진행 중인 대전과 저장·재접속은 유지한다. 개발자 운영 상태에서 활성 계정 방과 미정산·실패 상태를 확인한 후 패치를 배포한다. 점검 상태는 계정 DB에 저장해 재시작과 배포에도 유지한다. 저장 실패 시 신규 경기를 임시 차단하고 배포는 금지한다. `CARD_DUEL_MAINTENANCE=1`은 최초 DB 초기화의 기본값이며, 이후에는 DB에 저장된 선택을 사용한다.

개발자 계정에서 서버 접속 수, 진행 방, AI 작업 대기열, 저장 및 메모리 상태를 확인한다. 종료·이탈 경기의 AI 계산은 취소되며 대기시간 한도를 적용한다. `npm run online:load -- 12 8`로 로컬 합성 계정 동시 대전을 시험할 수 있다.

로컬 운영자 계정 DB의 무결성 검사 및 덮어쓰기 방지 백업(`npm run account:backup`)과 유저 자신의 진행 기록 다운로드를 제공한다. 복원 후 재로그인하며 XP·덱·전적·미정산 대전은 백업 시점 기준으로 유지된다.

성장 도구에서 가상 승률 35/50/70%의 승급과 카드 해금 판수를 비교한다. 카드/성장 설정 저장 전에 25×9 랭크 덱을 검증하며 호환 불가능한 패치는 기존 버전과 진행 기록을 유지한 채 거절한다. `npm run progression:simulate`로 성장 계산을 따로 확인할 수 있다.

랭크 AI 종료 화면에서 서버가 확정한 XP, 직업 퀘스트 보너스, 신규 카드 해금 및 승급 정보를 확인한다. 계정 화면에 25랭크 승급 조건과 9직업 퀘스트 진행표가 추가되었다.

**계정/성장/온라인:** 계정 등록 및 덱·진행 기록 서버 보존과 실시간 계정 동기화, 25단계 랭크 AI와 XP 해금, 9직업 순환 10경기 퀘스트, 보유 카드 PvP를 추가했다. 계정 경기 서버 재시작 복구, 미정산 보상·전적 재처리, 비밀번호 변경/세션 폐기, 개발자 성장 설정 화면까지 구현했다. `npm run balance`의 `/growth`에서 카드 획득 단계 및 AI 설정만 편집할 수 있다. `npm run verify:deployment`로 배포 사전 점검을 실행한다. 무료 호스팅 연결은 준비 단계이며 실제 외부 배포는 하지 않았다. 기존 오프라인 연습 모드는 그대로 지원한다. 설치, 테스트 및 운영 설정은 [계정·성장 온라인 개발 문서](docs/ONLINE_PROGRESSION.md)를 참고한다.

**친구 대전 연결 안정화:** 연결이 끊기면 5분 동안 대전을 일시 중지하고, 다시 연결하면 기존 손패·전장·시간 제한을 복구한다. 누락된 방 생성/참가 응답도 비공개 요청 번호로 복원할 수 있다. 상대가 5분 안에 오지 않으면 연결된 플레이어의 승리 처리; 둘 다 연결이 끊긴 방은 만료된다. `backup-ai-data.cmd`로 학습 중에도 원본을 중단하지 않고 현재 체크포인트를 다른 폴더에 보존할 수 있다.

**카드 밸런스 시험:** `start-balance.cmd` 편집기에 저장 전 수치 분석과 36/108/216경기 AI 비교를 추가했다. 기존 카드 또는 새 카드 초안을 집중 시험하고 원본·초안 승점률, 직업별 성적, 카드 손패/사용 횟수 및 승률을 비교할 수 있다. 실제 밸런스 및 AI 모델은 시험 중 변경하지 않는다. 종족·키워드·공통 효과도 버튼으로 편집할 수 있다. 자세한 방법은 [밸런스 시험 가이드](docs/BALANCE_LAB.md)를 참조한다.

**모바일 조작 및 전투 연출:** 손패를 좌우로 밀어 탐색하거나 위쪽으로 끌어 카드를 낼 수 있다. 터치로 선택한 뒤 화면에 표시되는 사용 버튼으로도 낼 수 있으며, 1초 길게 누르면 공개 카드 정보를 확대한다. 세로/가로 배치와 7개 하수인 표시를 개선했다. 연출 속도는 기본/빠르게/즉시 중 선택할 수 있다. 25단계 AI에 불완전 정보와 무작위 치명타 위험을 고려하는 실험 정책을 적용했다. 실제 휴대폰 조작 및 AI 강도의 통계적 입증은 별도 검증이 필요하다.

**솔로 대전 개선:** 상대 직업과 7가지 전략 덱을 선택하거나 무작위로 설정하고, 선공/후공을 지정할 수 있다. 설정과 최대 100경기 결과를 브라우저에 저장한다. 기기 AI 전투가 끝나면 같은 상대/덱으로 새로 섞어 재대전할 수 있다. 덱 편집기의 추천 덱에도 전략별 자동 생성 옵션을 추가했다.

**기기 AI 및 오프라인 솔로:** `solo-offline.html` 파일을 브라우저로 열면 서버 없이 실제 1~25단계 AI 대전, 덱 편집, 카드 보기, 전투 연출을 사용할 수 있다. `build-offline.cmd`는 현재 밸런스와 검증된 학습 결과로 파일을 다시 만든다. 일반 서버 게임에서는 기기 AI(기본)와 서버 AI를 선택한다. 자동/절전/최대 탐색 설정을 제공한다. Windows 및 Galaxy S24에서 실제 브라우저 동작은 아직 실기 측정이 필요하다.

**솔로 대전 저장/이어하기 (v0.45.0 검증 후보):** 기기 AI의 승인된 각 행동을 브라우저 IndexedDB에 저장한다. 대전 화면의 `저장 후 나가기` 버튼 또는 새로고침 이후 대전 준비 화면의 `이어하기`로 진행 중인 게임을 복원할 수 있다. 남은 턴 시간과 멀리건/카드 선택, AI 설정을 복구한다. 완료 대전 결과도 다시 볼 수 있다. 같은 카드 밸런스와 브라우저 프로필/사이트 주소의 저장소를 사용해야 한다. 다른 탭에서 최신 저장을 가져간 뒤에는 이전 탭의 저장을 막는다. 저장 불가 표시가 나오면 해당 경기의 변경 사항은 저장되지 않으므로 새로고침하지 않는다. 파일 직접 열기에서 저장소가 제한되는 브라우저는 `start-game.cmd`로 로컬 서버 게임을 열고 기기 AI를 선택한다. 실제 브라우저 IndexedDB E2E 및 Android/Windows 실기는 아직 미확인이다. 서버 AI/친구 대전에는 이 기능을 적용하지 않는다.

**오프라인 솔로 성장 (v0.92.0 개발 후보):** `solo-offline.html`의 솔로 랭크 유저 모드는 기존 성장 설정에 따라 보유 카드로만 25랭크 AI를 상대한다. 경기 결과와 XP/보유 카드/퀘스트/전적을 IndexedDB 동일 트랜잭션으로 저장하고, 중복 보상과 진행 중인 랭크 경기 덮어쓰기를 차단한다. 기존 전체 카드 연습은 XP를 지급하지 않는다. 성장 백업 JSON을 내려받고 새로운 로컬 성장 기록에만 복원할 수 있다(로컬 저장 덱·진행 경기 제외). 오프라인 백업은 수정 가능하므로 온라인 계정으로 인증 없이 가져오지 않는다. 파일 경로/브라우저 변경 전 성장 백업을 권장한다. APK는 아직 제공하지 않는다. Windows/Android 실제 저장 및 파일 다운로드·복원 시험 필요.

**모드 분리/덱 백업 (v0.93.0 개발 후보):** 첫 실행 유저 모드에서는 보유 카드로 랭크 대전을 진행합니다. 개발자 모드를 선택하면 전체 카드로 연습하거나 실제 랭크 1~25의 덱/지능을 시험할 수 있습니다(성장 보상 없음). 모드별 편집 덱은 독립적으로 저장됩니다. 덱 리스트에서 저장 덱 백업/추가 복원으로 덱 이름·30장 카드 목록을 옮기세요. 기존 덱은 덮어쓰지 않으며 이름 충돌은 별도 이름, 중복은 건너뜁니다. 오프라인 모드는 로컬 사용 편의를 위한 구분이며 온라인 권한과 별개입니다.

**CPU 학습 모드:** `train-ai-quiet.cmd` (절전), `train-ai-10h.cmd` (균형), `train-ai-max.cmd` (최대). 같은 카드 버전의 이어하기 결과를 공유하며 동시에 실행하지 않는다.

v0.31.0은 2014년 6월 클래식 기준 영웅 등급(Epic, 보라색) 38종을 추가하고, 남은 포인트 강조 그림 작업과 기존 카드 전용 그림 50종의 추가 제작을 완료한 버전이다. 전설 등급은 제외한다.

2014년 초기 하스스톤의 전투 시스템을 참고한 독립적인 1:1 카드게임 개발용 프로토타입. 현재 9개 직업, **382종의 덱 구성용 카드**(기본 133, 일반 94, 희귀 81, 영웅 38, 전설 36), 하수인/주문/무기/비밀, 웹 덱 편집기, 방 코드 대전 서버, 로컬 밸런스 편집기와 **혼자 하는 AI 연습 대전**을 구현했다. 2014년 6월 기준 직업 225종과 공용 157종의 대응 데이터를 구현했고 개발용 카드는 이전 버전으로 분리했다. 개별 카드의 모든 역사적 판정까지 동일함을 보장하지 않으며, 원작 코드·이미지·설명 원문을 추출하지 않았다.

v0.24.0은 전장 전체를 하나의 판타지 테이블로 재설계했다. 양쪽 영웅 초상과 무기·영웅 능력, 타원형 하수인, 부채꼴 손패, 오른쪽 턴 종료 버튼과 마나 수정, 종이 카드 프레임, 8장씩 넘기는 카드 도감, 턴 전환·소환·피해·카드 뽑기 효과를 적용했다. 배경과 프레임은 직접 작성한 SVG/CSS이며 실제 게임의 UI 리소스를 포함하지 않는다. 데스크톱 Chrome/Edge에서 1366×768 이상의 화면을 권장하고 F11로 전체화면을 켤 수 있다.

v0.32.0은 판타지 일러스트 364종(카드 관련 그림 355종과 전용 영웅 그림 9종)을 개성 중심의 회화형 디자인으로 관리한다. 배경에는 숲, 성벽, 선박, 동굴, 작업실 등 장소의 단서를 남기고, 중심 캐릭터와 물체에 중간 정도로 강한 채도 및 명암을 사용한다. 다양한 체형과 얼굴, 과장된 표정, 비대칭 포즈와 카메라 각도로 개성을 표현한다. 모든 380개 카드 정의에 알맞은 그림을 연결하며, 덱 구성용 카드 346종은 서로 다른 그림을 사용한다. 비수집 토큰·소환물은 생성 카드와 그림을 공유할 수 있다. 9개 영웅은 각자 별도의 초상화를 사용한다. 실제 마나, 공격력, 생명력/내구도, 효과는 카드 데이터에서 표시되며 그림 파일 안에 고정하지 않는다. 원작 이미지 파일 및 외부 이미지 API를 사용하지 않는다.

**1초 카드 확대:** 내 손패, 내 전장과 상대 전장의 공개 하수인, 공개 장착 무기와 내 비밀, 멀리건, 덱 편집 카드에서 마우스를 1초간 올리면 큰 카드와 전체 설명이 화면 옆에 나타난다. 전장 하수인은 현재 버프/피해/키워드와 침묵 여부를 표시한다. 마우스를 떼거나 Esc, 드래그, 클릭 시 닫힌다. 키보드 포커스로도 확인할 수 있다. 상대 손패/비밀은 공개되지 않는다.

**카드 세트:** 덱 편집기 상단의 전체 / 기본 카드 / 오리지널 카드 탭으로 구분한다. 전체 수집 카드 기준 기본 133종, 오리지널 일반 94종 + 희귀 81종 + 영웅 38종 + 전설 36종 = 249종이다. 영웅 등급은 보라색, 전설 등급은 주황색으로 표시하며 전설은 1장, 그 외는 2장까지 넣을 수 있다. 선택한 직업의 합법 카드 수를 탭에 표시하며 종류·마나·등급·직업·검색 필터와 함께 사용할 수 있다.

AI 대전과 친구 대전 모두 동일한 자체 그림을 사용한다. 오른쪽 상단 **자체 이름으로 / 클래식 이름으로** 버튼은 표시명만 변경한다. 활성 카드 JSON은 `v0.23.0.json`이며, 전설 카드의 공통 효과와 특수 판정이 전투 엔진에 추가되었다. 이전 학습 가중치는 `data/ai`에 보존되며 다음 버전으로 복사하기 전에는 해당 폴더를 백업한다. 오프라인 미리보기: `interface-quick.html`(작은 전투 전용 파일), `interface-preview.html`(모든 UI 샘플), `card-gallery.html`(전체 카드 도감). 첫 npm 설치에는 인터넷이 필요할 수 있지만, 설치 후 그림은 별도 인터넷 연결 없이 표시된다.

## 1. Windows 11에서 준비

1. [Node.js](https://nodejs.org/)에서 **24.x** Windows Installer (x64)를 다운로드하여 설치한다. npm이 함께 설치된다. 필요하면 설치 후 PowerShell을 새로 연다.
2. [Git for Windows](https://git-scm.com/download/win)를 설치한다. [VS Code](https://code.visualstudio.com/)는 코드 편집에 선택적으로 사용할 수 있다.
3. PowerShell 또는 Windows Terminal에서 다음을 각각 실행해 확인한다.

```powershell
node --version
npm.cmd --version
git --version
```

Node 버전이 `v24.x.x`이면 된다. PowerShell 실행 정책 때문에 `npm`이 막힐 때는 정책을 변경하지 말고 `npm.cmd`를 사용한다.

## 2. 게임 실행 (Windows)

압축 파일을 다운로드해 풀고 `card-duel` 폴더를 연다. 폴더 안의 `package.json`이 있는 위치에서 터미널을 연다(VS Code에서는 해당 폴더를 열고 `Ctrl + 백틱`).

가장 쉬운 방법은 Node.js 설치 후 `start-game.cmd`를 더블클릭하는 것이다. 처음 실행할 때 필요한 패키지를 자동 설치한다. `start-balance.cmd`는 밸런스 편집기, `test-game.cmd`는 타입 검사·자동 테스트·빌드 실행용이다. 아래 터미널 명령어와 동일한 동작이며 Windows에서 이 바로가기 자체는 직접 실행 검증하지 않았다.

```powershell
npm.cmd ci
npm.cmd run web
```

터미널에 `Card Duel: http://127.0.0.1:3000`이 표시되면 Chrome 또는 Edge에서 해당 주소를 연다. 서버를 실행한 터미널은 닫지 않는다. 종료하려면 `Ctrl+C`. 기본 서버는 안전을 위해 이 컴퓨터에서만 접근할 수 있다.

### AI와 혼자 테스트하기 (추천)

1. 브라우저 한 개에서 `http://127.0.0.1:3000`을 연다.
2. 대전 메뉴에서 내 직업의 문장을 선택한다. 직업별 입문용 추천 30장 덱이 기본으로 구성된다. 직접 덱을 편집하려면 **덱 편집하기**를 누른다.
3. AI 대전 영역에서 AI 직업과 AI 난이도(1~25단계, 기본 3)를 고르고 **AI 대전 시작**을 누른다. 방 코드나 다른 플레이어가 필요 없다.
4. 교체할 시작 카드를 클릭하고 확정한다. AI도 시작 카드를 선택한다. 녹색 윤곽의 손패 카드는 사용 가능, 금색 윤곽은 대상 선택이다. 손패의 카드를 클릭하면 선택만 되며, 하수인은 내 전장으로 끌어서 놓아야 소환된다. 주문은 전장 또는 유효한 대상에 끌어 놓는다. 공격은 하수인/영웅을 상대 대상에게 끌어 놓거나 먼저 공격자를 클릭한 뒤 대상을 클릭한다. 효과 선택 카드에는 별도 선택창이 뜬다.
5. 화면 오른쪽 턴 종료를 누르면 AI가 연출 재생 간격에 맞춰 행동하고 내 턴으로 넘긴다. 타격 순간에 결과가 반영되며, 연출 재생 중에는 다음 행동이 잠긴다. 오른쪽 위 효과음 버튼은 켜기/끄기이며 브라우저에서 한 번 클릭한 후 소리가 재생된다. 왼쪽의 카드 상세 및 최근 행동에서 효과와 판정을 확인한다. 잘못 선택했다면 Esc 또는 우클릭으로 취소할 수 있다.

AI 난이도:

| 단계 | 판단 방식 |
| --- | --- |
| 1 입문 | 무작위에 가까운 선택, 때로는 공격·턴 행동을 생략 |
| 2 쉬움 | 유리한 행동 후보 중 일부를 선택, 최선의 수를 놓칠 수 있음 |
| 3 보통 | 기존 AI: 카드와 교환의 즉시 결과를 평가 |
| 4 어려움 | 영웅 위험도, 공개 전장 압박, 인접 효과 배치까지 평가 |
| 5 전문가 | 상위 6개 첫 행동에서 두 번째 행동을 탐색하여 공개 정보 기반 연계·승리 기회 평가 |
| 6~11 전술/정예 | 점진적 탐색 깊이·후보 수 확대, 학습 가중치 사용 |
| 12~24 정예/챔피언 | 상대의 다음 턴 위협을 가상의 카드와 공개 전장으로 예측 |
| 25 최강 | 최대 8행동, 926개 노드 예산 및 반격 예측, 검증된 학습 가중치 |

모든 난이도에 동일한 덱·마나·체력·전투 규칙이 적용된다. AI는 상대의 숨겨진 손패, 덱 순서, 비밀, 실제 난수를 보지 않는다. 외부 API나 GPU가 필요 없다. 난이도는 탐색 예산 기준이며 모든 덱·상대에서 승률이 단계별로 엄격히 증가하거나 숙련 인간을 이긴다는 보장은 없다.

### 한 컴퓨터에서 친구 대전 테스트하기

1. 브라우저 일반 창과 시크릿 창(또는 다른 브라우저)에서 `http://127.0.0.1:3000`을 각각 연다.
2. 직업을 선택한다. 기본 추천 덱은 30장으로 구성되어 있다. 원하는 경우 덱을 비우고 카드를 눌러 추가하거나, 오른쪽 목록을 눌러 제거한다. 덱 이름을 입력해 저장하면 다음 접속에서 불러올 수 있다.
3. 첫 번째 창에서 **새 방 만들기**, 표시된 6자리 코드를 두 번째 창에 입력하고 **참가**를 누른다.
4. 두 플레이어가 교체할 시작 카드를 선택하고 각각 확정한다. 내 턴에 카드는 드래그로 내고, 영웅 능력 또는 공격 대상을 선택한 뒤 턴 종료를 누른다. 선택 효과가 있는 카드는 드래그 이후 효과 버튼을 선택한다. 카드 배치 위치를 지정할 수 있다. 양쪽에 동일한 공개 전투 연출이 각자의 시점으로 표시된다.
5. 브라우저 새로고침 시 같은 창의 기존 세션을 복구하도록 구현했다. 서버 종료 시 방/경기 상태는 초기화된다.

덱 편집기에서는 종류·희귀도·비용·직업/공용을 필터링할 수 있고, 평균 마나와 카드 종류 비율 및 마나 분포를 보면서 카드 30장을 구성할 수 있다. 편집 초안은 브라우저에 자동 저장되며 새로고침 후 유지된다. 카드가 모두 호환되는 이전 버전 초안은 새 밸런스 버전에서도 복구된다(이전 버전 초안은 보존). 실수로 제거한 카드는 되돌리기로 복구할 수 있다. 친구와 덱 공유하기를 펼쳐 공유 코드를 생성·복사하거나 붙여넣을 수 있다. 이전 개발 버전에서 저장한 덱이 현재 카드 풀과 맞지 않으면, 불러오기에서 호환 카드만 가져올지 확인한다. 원래 저장 덱은 삭제하지 않으며 부족한 카드만 추가해 새 이름으로 저장하면 된다.

### 같은 Wi-Fi의 친구와 테스트하기

서버를 실행할 컴퓨터에서 PowerShell `ipconfig`를 입력하고 사용 중인 Wi-Fi/이더넷의 IPv4 주소를 확인한다. 게임 서버를 종료한 뒤 `start-lan.cmd`를 실행하여 그 사설 IPv4 주소를 직접 입력한다. 예를 들어 `192.168.0.10`이라면 두 플레이어 모두 `http://192.168.0.10:3000`을 열고 방 코드로 참가한다. Windows 방화벽이 연결을 묻는 경우 신뢰하는 개인 네트워크에서만 허용한다. 공유기/방화벽 설정에 따라 연결이 제한될 수 있다.

### 서로 다른 인터넷망에서 접속 (선택 사항, 실기 검증 필요)

공개 포트 없이 사설 VPN으로 연결하는 방법을 준비했다. `docs/REMOTE_PLAY.md`에서 Tailscale 무료 개인용 옵션과 안전한 설정 방법을 확인할 수 있다. 외부 인터넷 실제 접속은 아직 검증하지 않았고, 외부 호스팅에 배포하거나 계정을 생성하지 않았다. 게임은 이 서비스 없이도 로컬에서 무료로 실행된다. 공인 IP로 직접 노출하거나 공유기 포트를 개방하지 않는다.

## 3. 자동 테스트 및 시범 경기

```powershell
npm.cmd test
npm.cmd run typecheck
npm.cmd run audit
npm.cmd run demo
npm.cmd run build
npm.cmd run test:render
```

추가로 `npm.cmd run stress -- 100`을 실행하면 현재 활성 카드로 100경기의 자동 대전을 진행하고, 게임 상태와 숨겨진 정보의 조건 및 실제 사용 카드 범위를 검증한다. 원하는 경기 수를 1~1000 사이로 지정할 수 있다.

`npm.cmd run stress -- 1 123`은 경기 번호 123의 시드와 덱을 재현한다. `npm.cmd run stress -- 500 0 epic`은 영웅 카드를 18장씩 넣은 덱의 500경기를 실행하고 영웅 카드 사용 범위를 검사한다. `npm.cmd run ai-smoke`는 9개 직업과 5개 AI 난이도의 45경기를 자동 진행해 최신 카드와의 호환을 확인한다. AI 강도 측정이나 학습은 수행하지 않는다.

`npm.cmd run benchmark:solo-journey -- 96 5100`은 새로운 검사 기록으로 실제 솔로 랭크 성장 경로를 실행하고 보상/보유 카드/직업 퀘스트/경기·성장 백업 왕복을 검증한다. `npm.cmd run benchmark:solo-journey -- 25 9000 --all-tiers`는 25개 독립 시작 프로필에서 모든 랭크의 실제 전투를 확인한다. 사용자 저장·카드·AI 학습 데이터는 변경하지 않는다. [솔로 성장 검증](docs/SOLO-JOURNEY-AUDIT.md) 참조.

`npm ci`는 잠금 파일 기준으로 필요한 TypeScript, React, Socket.IO, Vite와 테스트 도구를 설치한다. 유료 API/서비스는 없다. 자동 시범 경기는 실제 엔진을 사용한 두 자동 플레이어 대전으로, 경쟁용 AI는 아니다.

선택적으로 Windows에서 실제 브라우저 자동 테스트를 실행할 수 있다. 첫 실행 시 무료 Chromium 다운로드가 필요하다.

```powershell
npx.cmd playwright install chromium
npm.cmd run test:browser
```

제공된 Linux 개발 환경에서는 Chromium의 프로세스 소켓 권한 제한 때문에 브라우저 실행 테스트를 완료하지 못했다. 엔진/실제 Socket.IO 접속자/관리자 API 테스트 및 웹 빌드는 검증 완료했다.

## 4. 카드 밸런스 편집기

다른 터미널에서 다음 명령어를 입력한 뒤 `http://127.0.0.1:3001`을 연다. 편집기는 내 컴퓨터에서만 접근 가능하고 대전 서버와 분리된다.

```powershell
npm.cmd run balance
```

카드 이름이나 ID로 검색 → 카드 선택 → 비용, 공격력, 생명력, 효과 수치 수정 → 저장 전 검사 → 새 버전 저장 및 활성화. 효과 수치는 간편 편집란에서 숫자를 바꿀 수 있다. 새 효과나 대상·조건 변경은 고급 JSON에서 `docs/EFFECTS.md`의 허용 구조를 따라 입력한다. 능력치/효과 수치 변경 후 카드 설명도 실제 효과와 일치하도록 수정한다. 기존 JSON은 덮어쓰지 않으며 이전 버전으로 복원 가능하다. 활성 버전은 `data/cards/active.json`에 기록된다. 새 밸런스는 게임 서버를 재시작한 다음 경기부터 적용된다. 현재 게임 서버를 재시작하면 기존 방이 초기화되므로 경기가 끝난 뒤 재시작한다.

```json
{"id":"recruit","name":"신병","kind":"minion","class":"neutral","rarity":"basic","cost":1,"attack":1,"health":2,"tribe":"none","description":""}
```

`data/cards/v0.23.0.json`에는 382종의 덱 구성용 카드와 비수집 정의 55종이 있다. 동전 및 영웅 능력 전용 소환물은 엔진에 별도로 정의되어 있다(총 443종). 이전 `v0.22.0.json`의 346종, `v0.21.0.json`의 308종 데이터와 모든 예전 스냅샷을 그대로 보존한다.

이전 버전 선택에서 **선택 버전과 비교**를 누르면 활성 버전을 바꾸지 않고 추가/제거/변경된 카드를 확인할 수 있다. **현재 카드 복제해서 새 카드 만들기**를 열면 새 ID/직업/등급을 지정하여 신규 카드를 만들 수 있다. 생성한 초안은 검사를 통과한 후 새 버전으로 저장해야 게임 서버 재시작 시 반영된다. 영웅 카드를 제외한 이전 308종 범위로 돌아가고 싶다면 v0.21.0을 복원하면 된다.

## 5. Git으로 버전 보존

압축본에서 시작하는 경우 한 번만 다음 명령을 실행한다(이미 Git 저장소라면 생략).

```powershell
git init
git add .
git commit -m "Card Duel v0.32.0"
```

Git이 이름/이메일 설정을 요구한다면 이 저장소에만 `git config user.name "Your Name"`, `git config user.email "you@example.com"`을 설정한다. 예시 값은 실제 본인 값으로 바꾼다. 변경 이력을 별도로 보존하고 싶다면 `git log --oneline`으로 확인한다. `node_modules`는 커밋하지 않는다.

### Source-only candidate → playable PWA (Windows / Mac / Linux)

**Important:** a `card-duel-vNNN-candidate-source-and-verified-v197-play.zip` file contains
**source candidate v0.NNN**, but the included executable is still the previously
verified **v0.197**. Do not rename the old executable or publish the ZIP as v0.NNN.

To make an actual testable executable from a downloaded candidate ZIP:

1. Install Node.js **24** and ensure the computer can access npm. Extract the
   full candidate ZIP into its own empty folder (including `RELEASE-STATUS.txt`).
2. On Windows, double-click `BUILD-PLAYABLE.cmd`. On Mac/Linux, run
   `sh BUILD-PLAYABLE.sh`. Or run `node scripts/build-local-playable.mjs`.
3. The builder installs the *pinned* dependencies, checks approved data, then
   runs TypeScript, full engine/React, saved-game, ranked-duel, offline/PWA
   upgrade/rollback gates and actual Chromium landscape + save/resume tests. On success, `playable-release/` contains a new
   stand-alone HTML, a PWA ZIP, and a SHA-256 validation report.
4. Upload the **contents** of the new PWA ZIP to an HTTPS site; use the same
   origin as previous installations to preserve browser IndexedDB saves.
   Install it via the browser's “Add to Home Screen” / “Install app”.
5. Finish an actual Android/PC playthrough before calling a candidate a
   device-verified release. Packaging or automated tests alone do not verify
   physical touch, audio, orientation, or browser permissions.

If Node 24, dependencies, or any safety gate is unavailable, the builder
**fails without promoting the candidate**, and restores the included earlier
playable game assets. Keep the original candidate ZIP as a backup. The GitHub
Actions `Validate a playable Card Duel candidate` workflow is an alternative
when candidate sources have been pushed to a suitable GitHub branch.
